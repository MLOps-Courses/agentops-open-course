## Which terms do you need before Chapter 2?

Ten terms carry most of what Chapters 0 to 2 assume. Each one links to its full entry below.

- **[Agent](#agent)**: a model that chooses tools in a loop until it can answer — here, an on-call assistant investigating an incident.
- **[agentic loop](#agentic-loop)**: decide, act, observe, repeat: the model asks for a tool, the runtime runs it, the result shapes the next step.
- **[Tool](#tool)**: a typed function the agent may call, such as `get_service_status`.
- **[session](#session)**: one conversation's history and state, so the next turn knows what the last one said.
- **[ADK](#adk)**: Google's Agent Development Kit, the framework that runs the agent, its sessions, and its tools.
- **[MCP](#mcp)**: the protocol that lets an agent call tools living in a separate server instead of in its own process.
- **[A2A](#a2a)**: the protocol two agents use to find each other and exchange tasks across process boundaries.
- **[Guardrail](#guardrail)**: a check that runs in code around the model or a tool — for example, holding `restart_service` until a human approves it.
- **[Evaluation](#evaluation)**: a repeatable test of what the agent did, including which tools it called and in which order.
- **[doctor](#doctor)**: the staged `mise run doctor` check that says whether your machine has the tools the next tier needs.

- <a id="agentgateway"></a>**agentgateway**: The proxy placed in front of agents, models, and tools that enforces policy, auth, and observability. [5.0. Gateway](../5.%20Gateway/5.0.%20Gateway.md#why-add-a-gateway-after-the-agent-works)

- <a id="checkpoint"></a>**checkpoint**: The per-page verification exercise a learner completes to confirm the result before continuing. [0.0. Course](../0.%20Overview/0.0.%20Course.md#how-should-you-work-through-each-page)
- <a id="circuit-breaker"></a>**circuit breaker**: An opt-in reliability lever that opens after repeated read-tool failures so further calls fail fast, then lets one trial call test recovery. [3.1. Tools](../3.%20Capabilities/3.1.%20Tools.md#how-does-the-agent-shed-load-when-a-dependency-stays-down)
- <a id="composition-root"></a>**composition root**: The one module where an application constructs its runtime and wires dependencies together. [3. Capabilities](../3.%20Capabilities/index.md#which-capabilities-will-you-add)
- <a id="context-window"></a>**context window**: The maximum tokens a model can attend to in one call — instruction, history, tool schemas, and tool results together; exceeding it fails the request or silently drops old content, depending on the serving path. [2.2. Models](../2.%20Agents/2.2.%20Models.md#what-do-tokens-context-and-parameters-actually-mean)
- <a id="cosign"></a>**cosign**: Tool used to verify an image is the exact one CI built and signed. [6.1. Containers](../6.%20Platform/6.1.%20Containers.md#how-do-i-prove-an-image-is-the-one-ci-built)
- <a id="cosine-distance"></a>**cosine distance**: Embedding-similarity measure used by the optional semantic retrieval branch. [3.4. Memory](../3.%20Capabilities/3.4.%20Memory.md#when-do-embeddings-beat-keyword-retrieval)
- <a id="cost-attribution"></a>**cost attribution**: Assigning model and token cost to a session or tool for budgeting. [7.3. Costs](../7.%20Observability/7.3.%20Costs.md#how-do-i-attribute-cost-to-a-session-or-tool)
- <a id="data-plane"></a>**data plane**: The proxy layer every request passes through, where routing, rate limits, and content policy are applied. [0.3. Ecosystem](../0.%20Overview/0.3.%20Ecosystem.md#what-does-agentgateway-own)
- <a id="deadline"></a>**deadline**: A bounded time limit wrapping read tools so a slow dependency costs a retry, not a hang. [3.1. Tools](../3.%20Capabilities/3.1.%20Tools.md#what-happens-when-a-tool-hangs)
- <a id="delegation"></a>**delegation**: In-process transfer of control from a coordinator to a named sub-agent in the same process and session, cheaper and lower-latency than networked A2A but sharing one deployment, failure, and trust boundary. [3.6. A2A](../3.%20Capabilities/3.6.%20A2A.md#what-is-in-process-delegation)
- <a id="doctor"></a>**doctor**: The staged prerequisite check (`mise run doctor` and its `doctor:model`, `doctor:gateway`, `doctor:platform`, `doctor:gcp` profiles) that verifies exactly the tools a learning tier needs before you start it. [1.0. System](../1.%20Setup/1.0.%20System.md#what-does-each-doctor-profile-actually-check)
- <a id="dsar"></a>**DSAR**: Data-subject access request — a person asking what personal data you hold about them (or to erase it); the agent answers it per store, erasing memory while retaining the audit record. - <a id="embedding"></a>**embedding**: A vector representation of text that lets a search match meaning instead of exact words. [3.4. Memory](../3.%20Capabilities/3.4.%20Memory.md#when-do-embeddings-beat-keyword-retrieval)
- <a id="evaluation"></a>**Evaluation**: Repeatable measurement of behavior, trajectory, safety, or output quality — for example, checking that a question about an unknown incident calls `get_incident` with the right id and makes no unexpected write. - <a id="fallback-model"></a>**fallback model**: An opt-in secondary model, on the same account-free provider, tried only when the validated primary fails before responding. [5.4. Model Gateway](../5.%20Gateway/5.4.%20Model%20Gateway.md#how-does-the-agent-fail-over-when-the-primary-model-is-down)
- <a id="gate"></a>**gate**: A signal a machine evaluates deterministically, where a failure always means a defect a developer can reproduce and fix locally, so it can block a merge with no human in the loop. [4.3. Metrics](../4.%20Quality/4.3.%20Metrics.md#what-separates-a-gate-from-evidence)
- <a id="grafana"></a>**Grafana**: Dashboarding UI that visualizes the shipped AgentOps metric and log panels. [7.2. Monitoring](../7.%20Observability/7.2.%20Monitoring.md#which-dashboard-is-shipped)
- <a id="helm-chart"></a>**Helm chart**: A packaged, parameterized set of Kubernetes manifests installed as one named release; the course installs kagent this way, declared in `infra/helmfile.yaml` rather than typed at a prompt. - <a id="image-digest"></a>**image digest**: The `@sha256:…` content hash that names an image's exact bytes; unlike a tag, it cannot be re-pushed to mean something else, which is what makes a build reproducible. - <a id="groundedness"></a>**groundedness**: Whether an answer's claims are supported by retrieved evidence rather than invented. `eval:ground` deterministically checks recognized incident/severity and known service/runbook claims. - <a id="guarded-write"></a>**guarded write**: A state-changing tool (`restart_service`, `resolve_incident`) that cannot run on model output alone: it requires human confirmation, validates its target, and writes its mutation and audit record in one transaction. - <a id="guardrail"></a>**Guardrail**: Deterministic or model-assisted policy at an input, model, tool, or output boundary — for example, refusing a `restart_service` call until a human approves it. [4.5. Guardrails](../4.%20Quality/4.5.%20Guardrails.md#what-is-a-guardrail)
- <a id="hitl"></a>**HITL**: Human-in-the-loop: a human decision inserted before a sensitive action continues. [3.1. Tools](../3.%20Capabilities/3.1.%20Tools.md#how-does-human-confirmation-work)

Platform](../6.%20Platform/6.0.%20Platform.md#what-changes-when-the-agent-moves-to-kubernetes)

- <a id="long-term-memory"></a>**long-term memory**: Explicit cross-session notes a stable user can save and recall, isolated per user and PII-redacted before the write, distinct from per-session conversation state. ## How should you use this page later?

Come back here whenever a chapter uses a word you could not explain to someone else. Each entry gives you one line, then a link to the section that owns the term.

Keep the page open in a second tab while you read Chapters 1 to 3. That is when most of the unfamiliar names arrive, and a ten-second lookup beats guessing.

Reopen it for Chapter 6. It introduces the densest run of new vocabulary in the course — k3d, pod, Kustomize overlay, Helm chart, Skaffold, registry, image digest, Wolfi — and all of them are entries above.

**You are done when:**

- You can say what an agent, a tool, and a session are without opening another page.
- You followed at least one entry's link and landed on the section that introduces that term.
- This page is bookmarked, or open in a second tab, for the rest of the course.

Continue to [1. Setup](../1.%20Setup/index.md) when the ten starter terms read as familiar words rather than unknown names.
